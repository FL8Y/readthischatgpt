## 1. Architecture (ECS-style, server-authoritative)
- O: Engine is an entity/component/system runtime ("World", "Scene", "Runtime", `*Component`, `*System` names; commands like `wager:submit`, `power_up:select`, `choice_input:check`, `cloze:check`, `activity:timeout`, `attempt:completed`, `attempt:abandoned`, `marking:settled`, `question:marked`, `rewards:settled`, `timer:finished`, `host_gate:open`, `game:play_again`, `game:continue`, `game_playlist:advance|append`, `team:configure`, `interstitial:queue`).
- O: Hierarchy: Game -> (Game playlist of) Rounds -> Round Program (nodes incl. a `choose` node, submission marker, frontier, "beat permit") -> Activities (beats) -> Attempts (per player) -> SegmentAttempts -> Marking / EvaluationHistory.
- O: Generators (stateless) mint beats when the Round Program issues a "beat permit": question generator (from shared `question_source` buffer; may spawn pending placeholder), leaderboard/live-results/lobby/client interstitial generators, wager generator, power-up generator.
- O: Schema versioning via `...StateSchemaV128/V129`, `V130/V131`, `botPolicyV14ToV15`; migrators `mistakePolicyV128ToV129`, `evaluationPolicyV130ToV131`.
- O: Ticket refs APP-486..APP-621 appear in comments (e.g. APP-489/490/491/492/493 = Choice/Typing/Flashcard/Ordering/Matching Input; APP-581 answering preference; APP-582 flashcard reveal lock; APP-557 host-owned XP/coin application; APP-501 Standard compose default).

## 3. Question input kinds ("Inputs")
- O: Input = "Activity-owned ... one configured answering alternative with stable identity, explicit target Segments, authoritative CommitPolicy. No two Inputs of the same kind may cover the same target Segment."
- O Input kinds: **Choice** (MultipleChoiceInput), **Typing** (TypingInput, ExactTextSpeechTypingInput, SpeechTypingInput, ClozeTypingInput, ClozeSpeechTypingInput), **Ordering** (OrderingInput, ArrangementOrderingInput, SequentialOrderingInput), **Matching**, **Flashcard**; Cloze = compose host with per-blank Choice or Typing.
- O: Speech answering: `/v2/mark-speech-answer`, `evaluateSpeechInputForSegment`, speech-recognition permission.
- O: **Input Selection**: per-Attempt, `activeInputId` among `availableInputIds`, optional temporary override, default, selection reason, optional Flashcard reveal lock, targeted Segment, hinted options, skip intent, owner answer reveal.
- O: **Answering preference** (player-level, APP-581): `answering_preference:set`; "Mixed follows configured defaults"; temporary per-question Input switch does not change preference; automatic fallback never changes preference. Schemas `answeringPreferenceModeSchema`, `defaultAnsweringPreference`. Dual-method ("Choice+Flashcard co-tenancy", "dual-channel typing") exists; "Dual-method conflict needs explicit Activity policy".
- O **CommitPolicy** values seen: `on_change` (Choice, Ordering progression, Flashcard rating), `on_check` (Typing; Cloze per blank; "unchecked on_check drafts"), Matching "by completion"/fixed completion ("Matching CommitPolicy on_change requires fixed completion").
- O commands: Change (draft only; "does not assert correctness or spend the mistake budget"), Check (separate; `choice_input:check`, `cloze:check`), Submit (assesses all blanks incl. unchecked drafts, closes input; "Empty optional blanks skip rather than fabricate an answer"), Skip, Continue, Next.
- O Flashcard: front visible, back hidden until per-player reveal; then rate **Good / Not sure** (whole-card, single evaluation); Good opens host gate, Not sure waits for Continue; after reveal Input Selection locks to Flashcard until rating or Skip. Next/round deadline/leave finish as skipped without inventing a rating.
- O Matching state: pendingMemberIds, proposedGroups, achievedGroupIds, mistakes, feedback, feedbackUntilMs, commitments. Ordering state: placements, achieved positions, mistakes, position feedback, unavailable items. Tap order/visual column order never reach engine.
- O Free-response / AI: `buildFreeResponseExplainContext`, `buildProgramSceneExplain`, `buildStepExplainContext`, "step" moves (math/program-style steps; prompt text says not to reveal later steps/final answer) -> I: stepwise problem type with AI tutor.

## 4. Evaluation, mistake, skip, heart policies (all Activity-owned, shared by every player attempt, not overridable per attempt)
| Policy | Observed facts |
|---|---|
| **EvaluationPolicy** | O values `on_commit` (grades eligible commitments while Attempt open) and `on_submit` (defers grading until final Submit). Stamped by Choice, Ordering, Flashcard, Matching, Cloze, standalone Typing. `isSupportedEvaluationPolicy`, `rejectUnsupportedEvaluationPolicy` ("EvaluationPolicy does not support ..."). |
| **MistakePolicy** | O: "how incorrect evaluation results count, whether associated incorrect results retry or resolve incorrect, and the optional attempt-ending mistake limit". Counting: `per_commitment` (one mistake per evaluated commitment containing any incorrect result) or `per_incorrect_result`. Result handling includes `resolve_incorrect` (and retry). `mistakeLimit` positive integer or null (null = no limit). `isMistakeLimitExhausted`, `validateMistakeLimit`. Presets per input kind: `mistakePolicyPresetForInputKind`, `mistakePolicyForFlashcard`, `mistakePolicyForTyping`, `defaultClozeMistakePolicy`, `mistakePolicyFromChoiceStoppingRule`, `mistakePolicyFromMatchingBudget`, `mistakePolicyFromOrderingConfig`; defaults `DEFAULT_MATCHING_MISTAKE_BUDGET`, `DEFAULT_ORDERING_MISTAKE_BUDGET` (numeric values not in string table). `orderingMistakeLimitMode(Schema)`, `mistakeLimitMode`. Conflicting presets across alternative Inputs throw ("conflicting MistakePolicy presets across alternative Inputs"); `resolveActivityMistakePolicy` needs >=1 offered Input kind; live questions: `resolveLiveQuestionMistakePolicy`, `liveQuestionAuthoredMistakePolicy`, `liveQuestionOfferedMistakePolicyKinds`, `liveQuestionChoiceStoppingRule` (`choiceStoppingRuleSchema`). Flashcard rating resolves whole-card SegmentAttempt under MistakePolicy. |
| **SkipPolicy** | O: `skipPolicyModeSchema`, value `immediate`: "preserves resolved progress and rewards, skips unresolved SegmentAttempts, invalidates pending grading, finishes without waiting. Late results cannot change outcomes." Choice, Flashcard, Matching, Cloze stamp `immediate`. Other modes exist (enum not literally visible). |
| **Explicit Skip** | O: closes via family skip with reason `reveal` or `next`; keeps correct/achieved parts, marks remaining targets skipped, marks attempt skipped, completes participation; does not reverse final marks. Owner answer visibility follows `skipReveal` policy (`skipRevealPolicySchema`); never publishes a shared room reveal by itself. Post-skip behaviour: `postSkipReveal`, `postSkipNavigate`. Skip is a no-op in "disabled games, Continue-gated feedback, and non-skippable attempts". |
| **HeartPolicy** | O: "zero-or-one cost for an eligible incorrect assessed commitment and for a question timeout"; "Standard defaults both costs to one"; not derived from MistakePolicy. `HeartGateSystem`, `activityOffersHeartPolicyFamily`, `stampActivityHeartPolicy`, `DEFAULT_STANDARD_HEARTS_CONFIG`. |
| **HintPolicy** | O: "fixed successful-use cap or exhaustion until one distractor remains" (enum value `exhaust_distractors`); absence disables hints; stamped on Input Selection / Cloze host / child hosts. |
| **SubmissionPolicy / OutcomePolicy / BotPolicy** | O components exist (`SubmissionPolicyComponent`, `outcomePolicyState`, `BotPolicyComponent`, `botPolicyOverridesSchema`, `resolveBotPolicy`, `selectBotPolicy`, `disarmBotPolicy`). Contents not in strings. |
| **AccuracyTracking** | O: optional per Activity or Segment; `streak.requiresUnassisted` controls whether first-time-correct advances the correct streak; omitted = neutral; independent of RewardConfig. `firstTimeCorrect`, `correctStreak atLeast` (nonneg int). |

- O Segment `reviewMode` frozen on `segment:resolved` ("freeze completing Input kind onto SegmentAttempt.reviewMode"); `reviewModesForAttempt`.
- O Results: attempt outcome correct/incorrect/skipped; "abandoned" tag for left/disconnected players (attempt closes unanswered).

## 5. Hints and Explain
- O Hint: `HintCapabilityComponent`, `HintUsageComponent`, `HintPolicyComponent`; derived owner-visible hint affordance per Input (non-authoritative, rebuilt each turn). Messages: "No more incorrect answers available for hint" (Choice: eliminate a distractor), "No unmatched pairs available for hint" (Matching), "No next item available for hint" (Ordering), "Flashcards do not support hints". Telemetry `GAME_ORDERING_HINT_CLICKED`. Consumption is via inventory: `InventoryUseHintEvent`; "authoritative hint balance, by bucket"; `RunOutOfHintsModal`; "Early Hints" (paywall/offer); `hintsUnlocked` buff gate.
- O Explain: `ExplainComponent`, `ExplainSystem`, `ExplainButton`, `ExplainQuestionSheet/Modal`, `InlineExplainChat`, `canExplain`/`canShowExplain`. Data-less tag attached at spawn only if Round Program permit resolved Explain enabled (beat override, else scene default); absent = unavailable. Skip replaces/closes a pending explanation; Continue or paging away also closes it. `explainUnlocked` is a buff gate; AI chat (`ConversationQuestionExplain` events, `ai_explain_explanation`).
- O "Hide options initially" permit flag (question shows answering controls only after user asks); `selectAnsweringControls`.

## 6. Timers and pacing
- O Activity has a time limit (ms) read at start; on timeout "unanswered attempts are marked as skipped" (`activity:timeout`); question timeout also costs a heart (policy). Timers are host-scheduled one-shot (`createTimer`, absolute `dueAt` engine-clock ms so a late-waking host finishes immediately).
- O Constants (names only; values not in table): `LIVE_QUESTION_DURATION_MS`, `LIVE_RESULTS_DURATION_MS`, `LOBBY_DURATION_MS`, `POWER_UP_OFFER_DURATION_MS`, `WAGER_PLACEMENT_DURATION_MS`, `ORDERING_FEEDBACK_MS`, `INTERSTITIAL_DURATION_MS`, `UNTIMED_UNGATED_BEAT_PACING`, `LIVE_GAME_ACTIVITY_STALE_MS`, `DISCONNECT_GRACE_MS`, `HOST_DISCONNECT_GRACE_MS`, `LOBBY_DISCONNECT_GRACE_MS`, `GAME_SESSION_RELEASE_GRACE_MS`, `MISSING_GAME_GRACE_MS`, `LIVE_QUESTION_COUNT`. UI: `GameTimerBar`, `LiveGameTimerBar`, `LiveQuestionTimerBar`, "Lightning" mode (`LightningTimer`, `LightningMultiplierStore`, `gizmo.quiz.lightning-multiplier`) - I: speed-run mode with multiplier.
- O Early marking: "Every player has submitted ... answer methods mark now, without waiting for the time limit."
- O Idle: unanswered timeout on a tracked activity stamps idle marker on human; any client act clears it; bots never idle; idle players may stop being waited on (I).
- O Abandon: disconnect grace expiry or leave closes open attempts so others advance; a returning player can reopen an abandon-closed, never-submitted attempt if activity still live (not if answered/timeout/reveal-closed).
- O Play-again: countdown elapse -> force-finish round ("skip idiom as timeout"); `game_playlist:append` queues another round of same config.

## 7. Rewards: XP, coins, hearts, buffs
- O Reward model: "Reward-rule sibling under an Attempt or SegmentAttempt: item, eligibility expression, base calculator (fixed, timing-backed breakpoints, accuracy breakpoints, or timeDecay), stable authoredRef". "Inventory item is data - same entity family serves XP, coins, and yellow hearts." Components: `XpRewardComponent`, `CoinRewardComponent`, `SegmentXpRewardComponent`, `SegmentCoinRewardComponent`, `XpModifierComponent`, `CoinModifierComponent`, `SegmentXpModifierComponent`, `SegmentCoinModifierComponent`. Settlement: `RewardSettlement` pending -> finalized (`finalizedAt`) on `marking:settled`; crash-recoverable; account XP/coin application is host-owned after `rewards:settled`.
- O XP: constants `XP_PER_MARK`, `FLAT_XP_GRANT`, `STANDARD_ACTIVITY_STREAK_XP_MODIFIER`, `HARD_ROUND_XP_MULTIPLIER`, `LOW_QUALITY_XP`; buff stats `accuracyXpBonus` (+ `accuracyXpPowerFactor`, `bonusFactor`, "captured_buff ... requires scale role"), `correctXpMultiplier`, `hardRoundXpMultiplier`; `selectAwardedXp` multiplies policy amount by player's `xp_multiplier` (x1 if none). Anti-abuse: events `QUIZ_XP_FARMING_DETECTED`, `QUIZ_XP_LOW_QUALITY_RESTRICTED` + toasts (`xpFarmingToastShown`, `lowQualityXpToastShown`) - I: XP throttled for farming/low-quality decks. `first_game_bonus`, `essence_bonus` also appear.
- O Coins: `coin_flat` + one `coin_chance` roll per attempt resolved at `question:marked` into stored amount; `selectAwardedCoins`; cloze/owned-segment pots apply coin_flat on read, no chance roll. `applyCoinAccuracy`, `appliedCoinsDelta`. Coins purchasable (`/stripe/coins-checkout`, `^coins_(\d+)$` SKUs), earnable (`earn-more-coins`, invite = "1,000-coin contact invite" test), spendable on skipping cooldowns (`InventorySkipCooldownWithCoins`, `ImportSkipCooldownWithCoins`, `CoinSkipOffer`).
- O Buffs apply only to correctly-settled attempts; sourced from equipped collectables ("buff record aggregated from equipped collectables"); items like `accuracy-bonus-01..04`; `buffPerLevelLabel`, `buffValueAtLevel`; `*Unlocked` feature gates `hintsUnlocked`, `explainUnlocked`, `accuracyBonusUnlocked`.
- O Hearts (lives): **daily hearts** vs purchasable **super hearts** (authoritative inventory, `HEARTS_INVENTORY_CAPABILITY`); `/api/get_lives_info`, `/api/update_lives`; "lives refill generation" (`livesEpoch`) so a refill waives unapplied pre-refill charges (settle result `applied`/`waived`). **Yellow hearts**: per-game (per-sitting) state, NOT inventory; minted by `yellowHeartsChance` buff; credited on question/marking settle; consts `DEFAULT_YELLOW_HEART_MAX_BALANCE`, `SESSION_YELLOW_HEART_CAP`, `STANDARD_DEFAULT_YELLOW_HEART_SHARED_REWARDS`, `YELLOW_HEARTS_TYPE`, `YELLOW_HEART_AWARD_TYPE`; experiment `double-yellow-heart-experiment`. Heart icon colors Blue/Pink/Purple/Yellow exist (I: blue=daily?, pink=super? unverified). UX: "Out of hearts!", "Hearts are recharging", "Hearts restored!", "Running low on hearts" interstitial (invite friends to earn), `earn-more-hearts` route.
- I: heart charge flow = incorrect commitment or timeout -> heart consume request (cause-tagged, idempotent via epoch) -> block play at 0 (HeartGateSystem).

## 9. Wagers (live/team game beat)
- O Two-beat pattern: **placement beat** (timed interstitial) then **ridden question**. Content: stake bounds `min / max / step` (consts `DEFAULT_MIN_STAKE`, `DEFAULT_MAX_STAKE`, `DEFAULT_STEP_STAKE`, `defaultWagerStake`).
- O Command `wager:submit`: player picks a target **opponent**, predicts that opponent **correct or incorrect** on the upcoming question, and a stake; engine validates target, clamps stake, one bet per player per beat; if timer runs out `placed:false`. No target -> `LIVE_GAME_WAGER_NO_TARGET`.
- O Payout derived on read: won = +stake, lost = -stake, null while unmarked, attached as `wager_reward` on the bettor's own question attempt (nothing stored). Never scores by itself (power-up note says generator "never scores").
- O Cadence: `WAGER_CADENCES`, `LIVE_DEFAULT_WAGER_CADENCE`, `LIVE_WAGER_FREQUENCY`, `activeWagerFrequency`, `activeWagerMilestoneQuestionCount`, `collectWagerFrequencies`, `collectWagerMilestoneCounts`, `downcastBeforeWagerCadence`, value `before-wager` (I: wager every N questions or at milestone counts). SFX keys `game-wager-correct/incorrect/increase/decrease/placement`. Events `LIVE_GAME_WAGER_PLACED`.

## 10. Power-ups (live/team game beat)
- O Gated by flag `GAME_POWER_UPS_V1_FLAG`. Offer beat before a ridden question: each player is offered two rolled bank entries - a **boost** (affects self) and a **troll** (affects the assigned opponent). Rolled per player (eligibility differs). `power_up:select` carries no target; victim assigned server-side at beat open (in team games assignment maximises cross-team targets). One pick per player; timer expiry => boost auto-applied (`autoApplied`).
- O Effects: `PowerUpEffectsComponent` on ridden question attempts: list of landings each with kind/target/originator; **deflect/shield** returns a troll to the player who played it (appears as boost for shield, troll for receiver; may chain). Types `POWER_UP_KINDS`, `POWER_UP_CADENCES` (enumerations not visible). UI: `PowerUpCard/Strip/Sheet/Offer/Announcement`, `FlyingPowerUp`, `landedPowerUp`, `deflectedPowerUp`, `appliedPowerUp`. Telemetry `LIVE_GAME_POWER_UP_OFFER_SHOWN/PICKED/EFFECTS_LANDED`. "nothing consumes an effect id yet" (O: scoring effect wiring may be incomplete).
- O Round Program picks wager vs power-up group via a `choose` node.
